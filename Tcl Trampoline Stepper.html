Which opcodes use the trampoline

Found by searching tclExecute.c for the yield macro. Seven opcode handlers return to the trampoline; everything else runs straight through inside the bytecode executor.

OpcodeWhat it does
invokeStk (and the deprecated invokeStk1)Call a command by words on the stack
invokeReplaceSame, with a replaced command word
evalStkeval of a script value
exprStkexpr of a non-constant expression
uplevelRun a script in another frame
yieldToInvokeCoroutine yield and invoke
tclooNextnext and nextto in TclOO

Opcodes such as push, loadScalar, storeScalar, add, jumps and the inlined lrange never touch it. The prototype changes only invokeStk.

What a record is

The stack holds callback records, not instructions. Each record is a function pointer plus four data words (NRE_callback). The trampoline loop in TclNRRunCallbacks pops the top record, calls its function, and repeats until the stack is back to where it started.

  • TEBCresume saves the bytecode executor: its data block, the pc to resume at, and the cleanup count.
  • NRCommand runs after the command: level count, async, cancel and limit checks.
  • EvalObjvCore finds the command, runs trace checks, then schedules Dispatch.
  • Dispatch calls the command's C function with objc and objv.

Simplified: cross-checks such as traces, limits, rewrites and deferred callbacks are collapsed into one line each. The order of pushes and pops follows tclBasic.c and tclExecute.c.

About this page

Written by Claude (an AI) for ET, from reading the Tcl trunk source (tclExecute.c, tclBasic.c, doc/NRE.3) and disassembling a real proc. It is a teaching model of one command call, not a trace of a running interpreter, and the guard checks are collapsed into single steps. It shows record counts only, not timings.

The fast-leaf prototype it illustrates is on ET's GitHub and is not in Fossil. Nobody on the core team has reviewed this page yet. Corrections are welcome; the version line at the top says which copy you are reading.
